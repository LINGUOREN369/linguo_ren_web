# Task: write a quiz, mini quiz, pop quiz, review sheet, or exit ticket

Read first: `_claude/format.md` §1 (naming), §2 (style), §5 (assessments).
Model to copy: `PC 1.4 Quiz 1 v2 (30 pt).md` (PC) and the A2A Unit 1 quiz.
The key → `tasks/answer-key.md`.

1. **Confirm the scope** from the planning sheet and lesson plans. **Only test what has been
   taught.** (A past quiz tested parallel lines before they were covered. Don't repeat that.)
2. **Confirm points and time** if not given. Defaults are in `format.md` §5.
3. **Match the review sheet's difficulty** when one exists: same problem types, new numbers.
   Include one problem that requires thinking but isn't brutal.
4. **Build skills in steps** where it fits, e.g. factoring goes GCF → simple trinomial →
   leading coefficient ≠ 1.
5. Don't test the same skill twice (if 2c already checks extraneous roots, don't add another).
6. Solve every problem and confirm the numbers come out clean.
7. Deliver: the student quiz, plus an **instructor key with a rubric** (points per step,
   partial-credit rules). Both are printable when Mr. Ren asks for PDFs.

## Variants
- **Pop quiz:** given the day before a real quiz, announced the day before. On the simple side
  but enough to show students what they're missing. About 10 min.
- **Mini quiz:** about 8 points, 10–15 min.
- **Review sheet:** 8 practice sets in the practice-sheet format (`format.md` §3 → Review days),
  one part per quiz problem type, odd sets easier and even sets harder, plus its key. On a review
  day it is that day's practice sheet.
- **Exit ticket:** 1–3 problems on the day's core skill, about 5 min.
