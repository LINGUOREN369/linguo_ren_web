# Task: write homework

Read first: `_claude/format.md` §1 (naming), §2 (style), §3 (student handouts, Check Your Work).
The key for it → `tasks/answer-key.md`.

**Why homework is authored:** not to save time (the textbook pages are already assigned), but so
homework matches what actually happened in class. Classes often don't finish the planned material,
and recent mini quizzes / quizzes show what still needs work.

1. **Confirm what was actually covered.** Before writing, ask Mr. Ren (unless he already said) how far
   the class got and what the last mini quiz or quiz showed they need to work on. Also check the
   planning sheet's Content Gap column. Never assume the whole planned lesson was taught.
2. **Build from that**, not from the textbook, unless Mr. Ren asks for textbook alignment. Source:
   the day's lesson plan (walkthrough table + Watch-for column), limited to the parts covered, plus
   extra practice on the weak spots he named.
3. Cover **every skill that was covered** at least once, plus the **edge cases** flagged in
   Watch for (no solution, extraneous root, sign flip…).
4. Size it to **25–40 minutes** for 9th–10th graders. Estimate minutes per problem type and pick the
   count from that.
5. **Solve every problem before it goes in.** If a problem doesn't come out as intended (e.g. it gives
   an identity instead of one extraneous root), redesign it.
6. Write two notes:
   - `<COURSE> <unit> Day <N> Homework` (student): title, estimated time, problems, `<br>`
     writing space, and `## Check Your Work` with odd answers only.
   - `<COURSE> <unit> Day <N> Homework Solutions (Instructor)`: red-pen key per `format.md` §4.
7. Link both from the lesson plan's `attachments:` property and Homework section.
8. Check that the odd answers in Check Your Work match the key exactly.

**eText / textbook homework** (e.g. "eText Pg 350 #3, 6, 9…"): there is no student note to write.
Build only the key (`tasks/answer-key.md`), working the problems from the provided images.
